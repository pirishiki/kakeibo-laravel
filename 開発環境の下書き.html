イシュー #15「開発環境を作る」。上にいま決めることを置く。

⑧ 決定

元に戻すとき、戻す先にもとからある表をどうするか（レビューの指摘 中2）

決定：ア　いつも、戻す先を空にしてから戻す。 空にする前に、今の中身を backups\<名前>-<日時>-before-restore.sql に自動で保存する（印 23）。2026-10-12 に試した：余分な表を足してから戻すと、余分な表は消え、戻す前のファイルには余分な表が入っていた。

いまの db-restore.ps1 は、バックアップの中にある表だけを上書きします。バックアップにない表は、そのまま残ります。

困る例：10/12 にバックアップを取る → 10/20 に「口座」の表を足す（マイグレーション） → 10/25 に 10/12 のバックアップから戻す。
すると、「どの表を作ったか」の帳簿（migrations）は 10/12 の状態にもどります。ところが、口座の表は残ったままです。次に php artisan migrate を打つと、帳簿には「口座の表はまだない」とあるので作ろうとして、「もうある」というエラーで止まります。
おすすめ

ア　いつも、戻す先を空にしてから戻す

戻す前に、戻す先のデータベースを一度消して作り直す（中の表は全部消える）。戻したあとは、バックアップを取った瞬間とまったく同じになる。上書きの確認の文も「中身を全部消して戻します」に変える。

イ　選べるようにする（-Clean をつけたときだけ空にする）

ふだんは今と同じ（残す）。-Clean をつけたときだけ空にしてから戻す。どちらを使うか毎回考える必要がある。

比べる点ア　いつも空にするイ　-Clean で選ぶ
戻したあとの中身いつもバックアップと同じ-Clean を忘れると、上の困る例になる
覚えることなし-Clean の意味
表の一部だけ戻したいときできない（このアプリでは使う場面がない）できる
まちがえて戻したとき戻す先の今の中身は全部消える（確認の文で強く伝える）-Clean なしなら、ほかの表は残る

⑦ 決定

MySQL の中身を、どうやってファイルに保存し、どう元に戻すか（N-16）

決定：⑦-1 ア　mysqldump、⑦-2 ア　スクリプト 2 つ（scripts/db-backup.ps1・db-restore.ps1）。
  • イ（丸ごとコピー）を選ばなかった理由：MySQL を止める必要があり、別の名前のデータベースに戻せないので、よいところがない。
  • 2026-10-12 に試した：別の名前のデータベースに戻すと表の行の数がそろい、日本語と絵文字（家計簿 テスト（絵文字🍙））も化けなかった。
  • 動かし方は powershell -ExecutionPolicy Bypass -File scriptsdb-backup.ps1（この PC は .ps1 をそのまま動かせない設定のため。PC の設定は変えない）。日本語が化けないよう、スクリプトの先頭に BOM をつけた。

バックアップは、たとえると家計簿のノートをまるごとコピー機でとっておくことです。ノートをなくしても（データベースを作り直しても）、コピーから元に戻せます。合格の条件は「README の手順で中身をファイルに保存し、別のデータベースに戻すと、記録の件数と残高が同じになる」です（要件定義書 10 章）。

対象は自分の PC の MySQL（Docker の箱）です。本番の RDS は中身がテスト用のデータだけなので、取らないと決めています（全体構成設計書）。

⑦-2　手順の形

気をつけること：Windows PowerShell 5.1 で docker compose exec mysql mysqldump … > backup.sql のように > でファイルに書くと、PowerShell が文字の形（UTF-16）を勝手に変えます。日本語（相手の名前・分類）が化けたり、戻すときに MySQL が読めなかったりします。どちらの案でも、ファイルは箱の中で作ってから PC に写します。そのぶん、コマンドが長くなります。
おすすめ

ア　スクリプト 2 つにする

使い方.\scripts\db-backup.ps1.\scripts\db-restore.ps1 -File … -Database …

長いコマンドをファイルに書いておき、1 行で動かす。README にはこの 1 行と、確かめ方を書く。

使い方3〜4 行のコマンドを README から写して打つ

ファイルが増えない。中で何をしているかが README を読めば全部わかる。日付のファイル名は自分で打つ。

比べる点ア　スクリプトイ　手で打つ

  • 17保存先はリポジトリの中の backups/ フォルダにし、Git には入れない（.gitignore）。中身は自分のお金の記録なので、公開のリポジトリに入れてはいけない（N-06 と同じ考え）。

  • 21戻す先のデータベースは名前で選べる（最初は kakeibo）。合格の条件どおり、別の名前（例：kakeibo_restore）にも戻せる。上書きする前に確認を聞く。
  • 22いまは記録の表（records）がまだないので、今回は ある表の行の数がそろうかで確かめる。記録の件数と残高での確かめは、記録の機能を作ったあとにする（要件定義書 10 章のチェックはそのとき）。

考えたほかの案

Laravel のコマンド（php artisan db:backup のようなもの）を自分で作る、または部品（spatie/laravel-backup）を入れる。PC に mysqldump が入っていないので、結局 Docker の箱の中で動かすことになり、遠回りになる。

⑥ 決定

Dependabot に、何をどのくらいの間隔で見てもらうか

決定：ア　週 1 回（月曜 9 時）・小さな更新（minor・patch）は置き場ごとにまとめる。 見る置き場は composer・npm・GitHub Actions。リポジトリの設定で、あぶない穴のお知らせと直す PR もオンにした。ふだんの更新は master にマージしてから動く。

Dependabot は、GitHub が部品の新しい版を見はってくれるしくみです。たとえると冷蔵庫の賞味期限を見てくれる係。古くなった部品（新しい版が出た・あぶない穴が見つかった）を見つけると、「この版に上げませんか」という PR を自動で作ります。マージするかどうかは自分で決めます（自動ではマージしない）。PR には CI（test・lint・build）が動くので、上げても壊れないかがわかります。

いまこのリポジトリでは、Dependabot は何もオンになっていません（2026-10-12 に確かめた）。オンにするものは 2 つあります。

しくみ何をするかオンにする方法
あぶない穴のお知らせ＋直す PR（セキュリティ更新）使っている版に穴が見つかったら、すぐに知らせて、直る版への PR を作るGitHub のリポジトリの設定（コマンド 1 行ずつ）
ふだんの更新（バージョン更新）穴がなくても、新しい版が出たら決まった間隔で PR を作る。祝日の部品の更新もこちらリポジトリに .github/dependabot.yml を書く

① 部品の PHP（app/Livewire/RecordForm.php）

class RecordForm extends Component
{
    public $partnerId;
    public $categoryId;
    public $accountId;

    // 相手の欄が変わったら、自動で呼ばれる
    public function updatedPartnerId($partnerId)
    {
        $last = Record::where('partner_id', $partnerId)
            ->latest('date')->first();

        if ($last) {
            $this->categoryId = $last->category_id;
            $this->accountId  = $last->account_id;
        }
    }
}

① 決定

PHP・Composer・MySQL を、自分の PC のどこに置くか

決定：ア　PHP・Composer は Windows に直接、MySQL は Docker。Docker はサインインしたら自動で起動する。
  • MySQL の版（8.4）がリポジトリの compose.yaml に書かれるので、手元・CI・本番の版をそろえやすい。版がずれると「手元で動いたのに本番で動かない」が起きる。
  • Docker を手で起動する手間は、自動で起動する設定でなくす。PC のメモリは 32GB（ふだん 12GB ほど使用）なので、Docker が 1〜2GB 使っても困らない。
  • イ（Sail）を選ばなかった理由：Windows ではコードを WSL に移し、コマンドも全部 Docker 経由になる。本番は Docker を使わないので練習になりにくい。
  • ウを選ばなかった理由：起動の手間はないが、版が PC の中にしかなく、ずれても気づきにくい。

Laravel を動かすには、PHP（プログラムを動かす本体）、Composer（部品を入れる道具）、MySQL（データベース）の 3 つが要ります。置き方は大きく 3 とおりです。
